### 本周形成的关键原则

- 知识系统负责维护 Source、Document、Evidence 和审核状态；下游系统只消费已批准 Claim。
- 对“品牌发现力”的理解已从单纯 SEO 扩展为：被发现、被理解、被信任、被选择。
- AI 搜索知识的筛选标准已明确：保留可迁移的身份、证据、信任、技术可达性与内容结构原则；排除产品操作、固定预测、单一案例推论和投机性技巧。
- 市场信号是原始用户证据，不应未经聚合和人工确认就变成策略知识。

## 当前卡点

1. **检索召回不足。** 当前主要检索 Claim 的 topic、statement 和 recommended action，不覆盖文章标题、Evidence 或正文；多词查询偏向同时命中全部词，容易漏掉语义相关知识。
2. **下游消费方式尚未落地。** 项目可作为独立知识服务，但尚未决定业务侧是通过 API 获取 KnowledgePack，还是通过只读视图同步 approved Claim。
3. **局域网访问尚未配置。** PostgreSQL 和 API 都仅监听 `127.0.0.1`；另一台电脑无法访问是预期安全行为。开放局域网前需配置指定 IP 端口映射、防火墙白名单和只读角色。
4. **市场信号未形成洞察包。** 信号可以采集与浏览，但“多条信号 → 需求洞察 → 人工确认 → Brief 输入”尚未实现。
5. **跨文档知识治理待补。** 当前去重覆盖同 URL / 同正文；不同文章中的语义重复、冲突观点、时效到期和复审机制尚未建立。

## 本周学习或需要改进的问题

1. **知识数量不等于可用性。** 107 条 approved Claim 已能覆盖基础知识，但检索召回和任务匹配尚未验收；下一阶段应把“任务能否准确找到知识”作为核心指标。
2. **人工筛选规则需要持续固化。** 这周已识别出不应保留的内容：依赖具体工具语法、无边界的效果承诺、固定预测、单一案例外推和为凑数量而写的卡片。后续导入应继续按该标准执行。
3. **消费接口要早于跨机器部署。** 在决定 API 拉取还是数据库同步之前，不应开放端口或让其他电脑直接访问原始表；先确定数据契约，才能避免后续失效同步和权限返工。
4. **市场信号与知识需要保持分层。** 原始讨论适合发现问题与语言，不应自动升级为策略结论；必须有证据聚合和人工确认环节。
5. **文档快照需随数据同步。** 本次发现对接文档保留了 Semrush 扩充前的统计数据，已同步更新。后续所有带“当前数据”的文档应注明日期，并在阶段收尾时统一校验。

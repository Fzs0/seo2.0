# 市场信号与海外品牌洞察

## 目标

市场信号用于保存“用户正在讨论什么、困扰什么、如何评价方案”的原始证据。它与文章知识分开：文章适合沉淀可复用事实，市场信号适合发现需求、语言、场景和趋势，最后再为选题和写作提供证据。

帖子、评论、回复、论坛主题、评价、视频评论和私有导出内容都使用同一套信号格式；平台特有的认证、游标分页、限流、评论展开和字段映射由 Adapter 处理。

## 当前能力

- `POST /api/v1/knowledge/signals/import`：导入一批平台无关信号，要求确认有权保存和分析。
- `GET /api/v1/knowledge/signals`：按关键词、来源、内容类型、日期分页检索。
- `GET /api/v1/knowledge/signals/overview`：查看总量、近 7/30 天数量、平台和内容类型分布。
- 内容按来源+外部 ID或正文哈希去重；平台保存在信号自身的 `platform` 字段。
- 原始信号默认是 `new`，不会自动变成 Claim，也不会绕过 approved-only 知识检索门禁。
- Reddit 任务优先调用 `scrapi-reddit`；当公开 JSON 接口被平台拦截时，自动回退到 `crawlee[playwright]` 浏览器采集。
- YouTube 任务用 `crawlee[playwright]` 发现动态搜索结果，再用 `youtube-comment-downloader` 抓取视频评论和回复。
- 浏览器适配器读取 `KNOWLEDGE_BROWSER_CHANNEL`；Windows 本机可配置为 `chrome`，无需额外下载 Chromium。

当前前端的“市场信号 / 帖子与评论”工作区支持手动或 JSON 录入，也支持创建 Reddit、YouTube 和通用公开网页的定时采集任务；数据库迁移为 `004_market_signals` 和 `005_signal_crawl_jobs`。

## 下一层产品闭环

```text
平台 Adapter / 手动导入
        ↓
原始信号库 → 去重、语言/市场标记、线程关系、互动指标
        ↓
需求洞察草稿 → 痛点、任务、反对意见、购买触发、用户原话、趋势变化
        ↓
人工确认 → 洞察证据包
        ↓
写作 Brief / SEO 选题 / 内容日历
```

需求洞察必须保留证据引用，至少能回溯到多个原始信号；模型只能生成草稿，不能自动把未经确认的洞察注入 Agent 或对外发布。

## 平台接入顺序

优先接入能提供公开、稳定、可授权数据的来源：

1. Reddit、YouTube 评论和公开论坛：直接验证“问题—场景—用户语言”价值。
2. Google Trends、Search Console 或站内搜索：补充需求规模、搜索变化和自有品牌反馈。
3. X、TikTok、Instagram 等平台：在确认 API 权限、条款、成本和保存边界后接入；短视频平台要保留标题、描述、评论和互动快照，不假设存在统一正文。
4. 用户上传的 CSV/JSON、客服导出和调研结果：作为不依赖平台 API 的稳定补充渠道。

这些来源共享同一套 `SignalSourceAdapter` 接口，但不强行共享平台字段。采集任务应具备游标、断点、重试、限流、幂等和运行审计；平台连接器失败不能影响已入库信号和文章知识流水线。

## 使用边界

- 只采集公开且已确认有权使用的内容，保留来源 URL、时间和授权说明。
- 不把作者身份、联系方式或敏感个人信息作为趋势分析的必要字段。
- 对外发布前必须人工确认引用、代表性、时间范围和是否存在平台样本偏差。
- 趋势不是单条高互动内容；应结合时间窗口、内容量、独立作者数、互动质量和跨平台重复出现情况判断。

# 页面簇关联文章库存与策略候选方案

日期：2026-07-19  
状态：V1 已实现并通过本地真实数据库只读预演；尚未由用户在页面上手动验收，尚未执行正式策略。

## 目标

把 Strategy Builder 已完成的页面簇分析正式接入现有策略链，并保持一个页面簇最多形成一个页面级决策：

```text
Semrush 导入
  → 页面簇校验
  → AI 按页面簇分配站点
  → 同站文章库存匹配
  → new_article / update_article / Hold
  → 完整候选池
  → 人工配置今日计划
  → 人工审核后执行
```

## 固定处理单位

```text
business_id + assigned_site_id + topic_cluster_id
```

- 只处理 `validated / provisional` 页面簇；
- 每簇只读取 `pillar / standalone` 代表词一次；
- 匹配时携带簇内全部成员词、Semrush TOP10 URL 和目标资产 URL；
- 只匹配 AI 已分配的同一站点库存，不跨站自动改派；
- `bridge_review / split_review` 继续等待人工复核。

## 库存匹配证据

可靠匹配：

- 文章 URL 命中簇成员的目标资产 URL 或 Semrush TOP10 URL；
- 文章 `primary_keyword_id` 指向簇成员；
- 簇成员词与文章标题、slug、主关键词、Meta Title 或 Meta Keywords 完全一致或完整短语命中；
- 至少两个低频核心词高度重合。

弱匹配：只有一个站内低频核心词重合。弱匹配不能直接证明页面相同，也不能据此新写。

正文全文和 headings 不作为 V1 的独立匹配依据，避免 `vape / disposable` 等高频词制造误匹配。

## 业务决策

| 库存结果 | 候选动作 | 安全边界 |
| --- | --- | --- |
| 0 个可靠匹配，且没有弱匹配 | `new_article` | 每簇只生成一条新文候选 |
| 0 个可靠匹配，但存在弱匹配 | `Hold` | 人工确认意图前不新写 |
| 1 个可靠匹配，文章有明确诊断缺口 | `update_article` | 锁定真实 `post_id`，保留 URL |
| 1 个可靠匹配，文章没有规则命中的缺口 | `Hold` | 技术健康不等于主题完整，人工复核正文覆盖 |
| 1 个匹配，但正文或分析不可用 | `Hold` | 先恢复库存证据 |
| 2 个及以上可靠匹配 | `Hold` | 潜在关键词蚕食，只提供候选，不自动合并 |
| 同一文章同时承接多个页面簇 | `Hold` | 人工确认簇边界 |

AI 可以把本地候选降级为 Hold，但不能把已经锁定的库存事实从新写改成更新，或从更新改成新写。

## 复用与持久化

- 不新增数据库表；
- 继续复用 `seo_agent.tasks` 的 `content_audit / strategy_candidate / strategy_plan / seo_strategy`；
- 页面簇 ID 随内容诊断和策略候选保存；
- 候选稳定键优先使用 `business_id + site_id + topic_cluster_id + target + action`；
- 现有完整候选池、今日预算、站点配额、人工审核、执行和发布链保持不变；
- 合并、删除、301、canonical、跨站调整仍属于高风险动作，必须逐条人工批准。

可执行页面簇：96

新写候选：56 个簇
Hold：40 个簇

以上数字是纯函数和只读数据库预演结果，没有写入 tasks、没有启动策略、没有生成文章、没有外站写入。

## 当前闭环边界

本次完成的是“页面簇 → 库存 → 候选 → 复用现有人工计划/审核/执行链”的操作闭环。完整效果学习闭环仍需后续补充：稳定策略指纹、执行前基线、7/14/28/56/90 天结果快照、冷却和新证据解锁。

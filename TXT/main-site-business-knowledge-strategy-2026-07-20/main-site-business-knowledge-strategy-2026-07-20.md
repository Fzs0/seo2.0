# 主站业务知识与自动策略闭环方案

日期：2026-07-20
适用站点：产品主站（当前为 `exdivo`）

## 一、当前判断

文章、商业页面优化、社媒帖子和评论回复，都必须建立在同一套业务事实之上。站点地图只能说明有哪些 URL，不能单独说明产品卖点、适用人群、差异化和合规边界。

因此流程必须先建立业务知识，再生成策略：

```text
产品/页面/资料/竞品证据
  → 业务事实与 Claims
  → 人工确认知识画像
  → 多渠道策略候选
  → 人工批准
  → 执行与发布
  → 效果追踪
  → 新证据反哺下一轮策略
```

## 二、知识画像 V1

知识画像至少包含：

- 产品：名称、功能、规格、使用场景、适用人群、价格/套餐和限制；
- 市场：核心卖点、购买理由、用户疑虑、同类产品差异；
- 证据：认证、测试、评价、案例、官方数据和来源页面；
- 内容边界：应该写什么、不应该写什么、不能承诺什么；
- 转化关系：产品页、分类页、FAQ、支持文章和内链方向；
- 时效：来源、确认状态、版本、更新时间和失效条件。

知识生成只产生 `draft`。关键事实必须人工确认，未确认或无来源的事实不能进入可执行策略。

## 三、实现顺序

### Phase 1：主站业务知识

复用现有站点 `knowledge_profile`，先不新增迁移表：

1. 使用已上传的 `products / collections / pages / posts` 索引和页面扫描结果；
2. 合并产品数据、已有文章、FAQ/品牌资料和人工补充资料；
3. 生成结构化产品事实、差异化、证据和内容边界；
4. 在站点页面展示、编辑并确认知识画像；
5. 保存来源和确认状态。

独立 Knowledge 服务后续作为 Claim 检索和证据审计层接入，不能在主业务未接入前假设它已经参与策略。

### Phase 2：主站 SEO 策略适配

复用现有候选池、今日计划、审核、执行和效果追踪，增加主站专用规则：

- 产品页/分类页是商业承接目标；
- 支持文章负责解释搜索需求和建立内链；
- 有已有文章时优先生成更新策略；
- 没有覆盖时生成新文章策略；
- 没有确认知识、证据或转化目标时进入 `Hold`；
- 每个候选必须带 `conversion_target`、证据和预期结果。

不要直接打开主站普通博客策略开关，主站应由 `commercial_hub` 规则进入策略范围。

### Phase 3：统一多渠道动作

统一使用策略候选和审批链路，动作类型预留为：

- `seo_new_article`；
- `seo_update_article`；
- `seo_update_page`；
- `social_post`；
- `comment_reply`。

第一版只实现 SEO 新文和已有文章优化。社媒和评论动作先进入候选池，待平台连接器、权限和风险规则明确后再执行。

### Phase 4：自动闭环

```text
上传资料/索引
  → 知识过期
  → 生成知识草稿
  → 人工确认
  → GSC/SERP/页面诊断
  → 生成候选池
  → 生成今日计划
  → 人工批准
  → 生成/发布/回读
  → 记录排名、点击、访问和转化
  → 再次规划
```

外站写入继续保留人工批准；完全自动发布需要单独的风险授权和逐步自治设计。

## 四、完成标准

- 系统能说明产品卖什么、适合谁、特征和差异化；
- 关键事实都有来源或明确标记为待确认；
- 每个主站文章候选都绑定产品页或分类页；
- 策略能区分新增文章、更新文章和商业页面优化；
- 发布结果能回读并进入效果追踪；
- 新证据能够触发下一轮策略重新评估；
- 社媒和评论动作与 SEO 使用同一套知识和审批边界。

## 五、当前状态

- 主站索引：用户已通过本地上传完成，默认支持覆盖；
- 主站知识画像：可以生成和人工确认，但业务事实结构仍需加强；
- 通用策略闭环：已有博客/WP 策略能力；
- 主站策略：尚未接入商业页面到支持文章的专用候选规则；
- 社媒/评论：尚未接入执行连接器；
- 自动发布：仍受人工审核和外部写入边界约束。

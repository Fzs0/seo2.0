# 关键词导入与页面簇准备流程 V1

状态：流程设计已固化；Strategy Builder 分支的导入、本地页面簇校验、按簇 AI 站点分配、同站文章库存关联和页面簇候选生成已实现并通过真实数据只读预演；尚待页面手动验收，其他来源分支尚未实现。

## 1. 统一目标

所有来源先保存原始证据，只做可解释、可重复的本地整理，不在导入时删除关键词、分配站点或执行策略。不同文件按其已有证据分流，最终都汇合为“可校验的页面簇”。

```text
导入文件
  → 通用数据检查（规范化、去重、市场/语种、数值有效性、保留 raw）
  → 按来源能力分流
      Strategy Builder：保留 Topic / Page / Page type / TOP 10，直接校验页面簇
      Topic 列表：Topic 仅作暂定主题，后续取得 SERP 后建立页面簇
      基础关键词：先生成暂定 Topic，再取得 SERP 后建立页面簇
      GSC 排名词：先按真实排名 URL 归组，缺口再补 SERP
  → 页面簇边界校验
  → AI 按页面簇判断语义、意图和目标站点
  → 关联文章库存
  → 形成新写、更新/扩展和关键词蚕食 Hold 候选
  → 人工计划与审核
```

`Topic` 是内容体系的大主题，`Page` 页面簇才是后续写作和库存匹配的基本单位。基础关键词文件没有 `Page` 和 SERP 证据时，不套用 Strategy Builder 的页面簇规则。

## 2. Strategy Builder 页面簇校验 V1

规则版本：`keywordImportPolicy.version = 1.0.0`，随 `seo-standard` 规则集版本化保存。

- 先规范化 TOP 10 URL：主机名忽略大小写和 `www`，去掉 fragment、默认端口、尾斜杠及 UTM/gclid/fbclid 等追踪参数；保留 YouTube `v`、站内搜索 `q` 等决定真实页面内容的参数。
- 每个关键词至少需要 7 条有效 SERP URL；证据不足进入 `split_review`，不自动删除。
- 强重合：TOP 7 至少共享 3 个 URL，或 TOP 10 至少共享 4 个 URL。
- 可接受重合：TOP 10 至少共享 3 个 URL。
- 页面簇中心词采用 SERP 重合度 medoid；同分时依次参考 Volume、KD 和关键词文本。

四种结果：

| 状态 | 业务含义 | 下一步 |
| --- | --- | --- |
| `validated` | 所有成员与中心词均达到强重合 | 可进入按簇 AI |
| `provisional` | 所有成员与中心词至少达到可接受重合 | 暂保留，可进入按簇 AI并保留复核标记 |
| `bridge_review` | 簇内可通过强关系连通，但部分成员与中心词较弱 | 先人工复核边界 |
| `split_review` | 证据不足或存在无法连通的成员 | 补查 SERP 或拆簇 |

这些状态不改变 Semrush 原始 `Topic / Page / Page type`，也不阻止结构正常文件的确认导入。校验结果随每行原始数据保存在 `_strategy_builder.cluster_validation`，供下一阶段按簇 AI 使用。

## 3. 当前实现边界

已实现并验证：

- Strategy Builder `.xlsx` 只读预览与人工确认导入；
- 页面簇中心词、四类边界状态和汇总计数；
- 对已导入批次重新执行相同规则并持久化结果的入口；
- 仅对 `validated / provisional` 中心词执行一次 AI，并把同一结果写回整个页面簇；
- AI 只能从同业务、同市场和同语种的启用站点中选择；无法确认时整簇 Hold；
- 文章库存关联只处理已分站的页面簇代表词，并携带全部簇成员；可靠匹配 0 篇形成一条新写候选，1 篇且有诊断缺口形成更新候选，多篇形成蚕食 Hold，弱匹配形成复核 Hold，单页匹配但没有语义覆盖证据也保持 Hold；
- 页面簇候选继续进入现有完整候选池、人工计划和人工审核链，不新增策略旁路；
- 真实文件 `E:\Keywords\vape_pages_2026-06-25-US.xlsx` 本地回归。

尚未实现：

- Topic 列表、基础关键词和 GSC 来源的自动能力识别与补证据流程；
- 边界不清时自动调用 SerpApi；
- `bridge_review / split_review` 的人工拆簇编辑和补查界面。

2026-07-19 真实数据库只读预演：96 个已分站簇关联 108 篇同站可用文章，56 个形成新写候选，40 个进入 Hold（3 个潜在蚕食、2 个跨簇边界冲突、25 个弱匹配复核、10 个正文覆盖复核）；13 篇独立文章技术更新中有 2 篇涉及页面簇 Hold 并被隔离，最终保留 11 篇，合计 107 个候选。此次预演未写入任务、未执行策略。

## 4. 安全边界

- 导入和本地校验不自动删除关键词、不拆簇、不分站、不生文、不执行策略。
- AI 只在页面簇形成后运行一次，不逐关键词批量分站。
- 站点分配必须受业务、市场、语种、站点知识和文章库存约束。
- 新写、更新和蚕食判断只生成候选，继续经过人工计划与审核。
